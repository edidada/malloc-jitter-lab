[  ctrl-log] n=10000  mean=4112.4ns  P50=3697ns  P90=5851ns  P99=10339ns  P999=39153ns  MAX=330411ns

知识点：
 1. std::string += / vector push_back 都可能触发 realloc。
 2. 控制路径上任何 STL 操作都可能是隐形 malloc。
 3. 修复：reserve() 预分配 + 固定容量 ring buffer，见实验 06。

== [6/6] 06_memory_pool_fix: 内存池修复对照 ==
== memory pool vs glibc malloc ==

-- phase: raw glibc malloc --
[ control] n=2000  mean=65.0ns  P50=40ns  P90=120ns  P99=280ns  P999=571ns  MAX=18394ns

-- phase: thread-cache pool --
[ control] n=2000  mean=55.5ns  P50=50ns  P90=61ns  P99=291ns  P999=571ns  MAX=671ns

知识点结论：
 1. 每线程独享池（thread-cache）完全绕过 glibc arena 锁，无 CAS、无 ABA。
 2. 全局 CAS freelist 有 Treiber-stack ABA 竞态，本实验真实踩坑：
    同一块被双重分配，memset 填充 0xEF 被当作 next 指针 → SIGSEGV。
 3. 生产方案：tcmalloc/jemalloc 的 thread cache，或 boost::pool。
 4. 别忘了：先 reserve/预分配，再进入实时控制段。
